# Building the Android APK

This produces a single installable `.apk` containing the **mobile UI only**
(the old desktop/browser view is not included). It's a debug-signed APK —
that's fine for sending to one person to sideload; it does not need to go
through the Play Store or any release signing.

## Prerequisites

- **Node.js** (any recent version — this was built with v24).
- **Android Studio**, installed once so its bundled JDK and the Android SDK
  are on disk. You don't need to open a project in it for this to work —
  the CLI build below only needs the SDK/JDK it ships with.
  - SDK expected at `%LOCALAPPDATA%\Android\Sdk` (Android Studio's default
    install location on Windows). This needs `platform-tools` and at least
    one `build-tools`/`platforms` version — Android Studio's SDK Manager
    installs these automatically the first time you open it.
  - JDK: Android Studio bundles its own ("JBR") at
    `C:\Program Files\Android\Android Studio\jbr` — you do **not** need a
    separate Java install.

Set these two environment variables before building (PowerShell):

```powershell
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
$env:PATH = "$env:JAVA_HOME\bin;$env:ANDROID_HOME\platform-tools;$env:PATH"
```

(Adjust the Android Studio path if you installed it somewhere else.)

## One-time setup

```powershell
npm install
```

This pulls in Capacitor (`@capacitor/core`, `@capacitor/cli`,
`@capacitor/android`, plus the app/status-bar/splash-screen plugins) and
`@capacitor/assets` (used once already to generate the app icon/splash —
you don't need to re-run that unless you change `resources/icon.png`).

## Building the APK

```powershell
npm run build:apk
```

This runs three steps back to back:
1. `build:mobile` — assembles `dist/mobile/` (the offline HTML/CSS/JS bundle,
   see below).
2. `npx cap sync android` — copies `dist/mobile/` into the native Android
   project and wires up the Capacitor plugins.
3. `cd android && gradlew.bat assembleDebug` — compiles the native shell and
   packages everything into an APK.

The first Gradle run downloads Gradle itself and some dependencies, so it
can take a few minutes; after that it's much faster (30–60s).

**The APK lands at:**
```
android/app/build/outputs/apk/debug/app-debug.apk
```

If you only want to rebuild the web bundle without touching the Android
project (e.g. while iterating on `ui/`), `npm run build:mobile` alone is
enough — you only need `build:apk` again when you want a new `.apk` file.

### macOS/Linux

Same steps, but use `./gradlew assembleDebug` (no `.bat`), and Android
Studio's bundled JDK lives at a different path (e.g.
`/Applications/Android Studio.app/Contents/jbr/Contents/Home` on macOS).

## Sending it to your brother

1. Copy `android/app/build/outputs/apk/debug/app-debug.apk` to his phone
   (email attachment, a cloud drive link, USB cable, whatever's easiest —
   it's one ~6MB file).
2. On his phone, he opens the file from wherever he saved it (Downloads,
   Files app, etc.) and taps it.
3. Android will refuse to install it the first time and offer a settings
   shortcut — something like **"For your security, your phone is not
   allowed to install unknown apps from this source."** He taps that,
   then enables **"Allow from this source"** for whichever app he opened
   the file with (usually "Files" or his email/chat app). This is a
   one-time toggle per source app, not a system-wide setting he has to
   remember.
4. Back out to the file and tap it again — it now shows the normal
   install screen ("Football Agent Manager wants to install this
   application"). Tap **Install**, then **Open**.

No Google account, Play Store, or internet connection is required at any
point — the app is fully self-contained and offline once installed.

## What's actually in the bundle (`dist/mobile/`)

Generated by `scripts/build-mobile.js`, which copies only what the mobile
UI needs:
- `index.html` (portrait viewport, theme-color, self-hosted fonts/icons)
- `engine/` — the shared game-logic JS (`storage.js`, `game-state.js`,
  `simulation.js`, etc.) — the exact same files the desktop UI uses, just
  copied rather than shared by relative path, since the desktop UI and its
  `styles/` folder are deliberately left out of this bundle entirely.
- `js/` — the mobile screens, router, and boot sequence (`ui/js/*.js`)
- `files/`, `app.css` — the three CSS files (design tokens, shared
  components, mobile app styles)
- `vendor/` — self-hosted Inter (woff2, weights 400/600, latin + latin-ext)
  and the Tabler icon webfont — **zero CDN links remain**; the bundle was
  verified to make no network requests at all (see test checklist below).

## Notes on the native wrapper

- `capacitor.config.json` sets the app ID (`ch.jens.footballagent`), app
  name, and `backgroundColor`/splash/status-bar colors to match the game's
  `--bg` (`#0F1318`).
- Portrait is locked in `android/app/src/main/AndroidManifest.xml` via
  `android:screenOrientation="portrait"` on the main activity.
- The app icon is a mint shield on `--bg`, generated from
  `resources/icon.png` (+ `icon-foreground.png`/`icon-background.png` for
  the adaptive icon, `splash.png` for the launch screen) via
  `npx capacitor-assets generate --android`. Re-run that command if you
  ever change the source images in `resources/`.
- The `INTERNET` permission is present in the manifest — this is a
  Capacitor/WebView requirement for its internal local-content loading
  mechanism, not an indication the app calls out anywhere. The bundle was
  verified to issue zero external network requests (see below).
